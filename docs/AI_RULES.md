# AI Agent & Vibe Coding Guidelines (厳守事項)

このプロジェクト（HERON）は既に基本機能とUI（外見）が完成しています。
あなたは既存のコードベースを自社ポータルサイトへ統合するための改修・テストを行うために召喚されました。
**以下のルールをいかなる場合でも絶対に遵守してください。**

## 1. 既存コードの改変禁止 (DO NOT MODIFY EXISTING CODE)
- **UI/コンポーネント:** `frontend/src/` 配下の既存のUIコンポーネント、デザイン（Tailwindクラス）、レイアウトのコードを**直接変更してはいけません**。外見の変更はユーザーから明確な指示があった場合のみ行ってください。
- **ビジネスロジック:** `backend/internal/service/` などの既存のコアロジックは完成品です。バグ修正を除き、既存の関数や振る舞いを書き換えないでください。

## 2. 拡張時の原則（Adapter パターンの推奨）
- 既存の処理に手を入れる必要がある場合（例：ポータルサイト連携のための新しい認証フローの追加など）は、既存のコードを破壊するのではなく、**新しいディレクトリやファイル（例: `backend/internal/portal_auth/`）を作成**し、そこで実装してください。
- 既存システムへの影響を最小限に抑えるため、エンドポイントを追加する場合は `/api/portal/...` のように分離してください。

## 3. 実行前の確認事項
- ターミナルコマンドを実行してファイルを書き換えたり、既存ファイルを一括置換（sed等）したりする操作は極めて危険です。行う前に必ずユーザーの許可を得てください。
- パッケージの追加や依存関係（`package.json`, `go.mod`）の更新が必要な場合は、影響範囲を報告し同意を得てから実行してください。

## 4. 統合テストにおける振る舞い
- 統合テスト（インテグレーションテスト）のコードを書く際は、既存の実装コードにテスト用の分岐を埋め込むようなハックを行わないでください。外部からAPIを叩く、またはモックを注入するクリーンな方法を採用してください。
